0. 主线一句话#

Task2 关心的是「智能体靠什么知道」：06 讲把静态文献变成可检索、可引用的知识库，把动态实验过程变成跨会话记忆；07 讲把散落在论文里的科研数据变成可验证、可发布的 AI-Ready 数据集。

三者是同一条证据链上的三个环节，各缺一块都不成立：

  • 知识库解决「查得到」——公共、静态、有引用。
  • 记忆解决「接着做」——个人、动态、跨会话。
  • 数据集解决「别人能接着做」——结构化、可追溯、有治理。

一句话记：知识库管查得到，记忆管接着做，数据集管别人能接着做。

1. 起点：模型的三个缺口，两类外挂（06-P3、P4、P7）#

06 讲开头就把问题摆清楚了：大模型训练完参数就冻结，你的资料、偏好、项目进展它一概不知道（06-P3）。落到科研场景，缺口有三个（06-P7）：

缺口 课件表述 后果
知识过时 大模型知识截止到训练日期 查不到最新进展，前沿方向尤其明显
私有盲区 你的 PDF 是私有的，预训练时从没见过 本地 200 篇文献，AI 等于「没读过」
幻觉 一次性塞入过多上下文，模型会胡说或丢重点 答案看起来流畅，实际经不起核对

对策是外挂两样东西：知识库（查得到）＋记忆（记得你）。RAG 是连接文献库与模型的那座桥，桥的四段是：切分 → 嵌入 → 检索 → 生成（06-P7）。

这里有个我认为很重要的判断：用文件夹分文献已经算「做了一半的 RAG」（06-P4）。

  • 按章节建文件夹、让 AI 助手管理，本质也是检索增强；
  • 但没分块、没索引，AI 只看得到标题，每次都要全量重读，慢、费 Token、定位不准；
  • 知识库的做法是把「你已经有的习惯」做到位：提前解析、切分片段、按需精准召回、可溯源到原文段落。

换句话说，RAG 不是新发明的需求，而是把「翻文件夹」这件事工程化。

2. RAG 的四个词与五步闭环（06-P8~P12、P15）#

2.1 四个词先记住（06-P8）#

术语 英文 课件定义 我的记法
嵌入 Embedding 把文本转成高维向量，让 AI 理解语义 把「意思」翻译成「坐标」
召回 Recall 从知识库检索并提取相关片段返回给模型 先捞一批候选
重排序 Rerank 对召回结果二次精排，把最相关的排前面 再排一次队
检索 Retrieve 广义的信息查找，包含召回、重排等整套动作 「查」的总称

课件特别点了一句：检索是包含召回和重排的整套动作，不是单指某一步（06-P8）。日常说「检索效果不好」时，先分清是召回没捞到，还是捞到了但没排上来——这两类问题的修法完全不同。

2.2 建库三步（06-P9）#

步骤 做什么 课件参数
1. 切分 Chunk PDF → 小段文本 500 字/段
2. 向量化 Embedding 文本 → 高维向量 768 维
3. 存储 Vector DB 向量 → 向量数据库 语义近则距离近

课件在两处口径略有差异：06-P9 写「500 字/段」，06-P12 写「500 tokens/段」。工程上按 token 更准（切分要受模型上下文约束），但不必纠结数字，重点是一段只装一个语义单元。

课件用一张三维坐标图解释「语义位置」：意义相近的论文在向量空间里「挨得近」，这不是地理位置，而是语义位置（06-P9）。图里同时摆了 K-Means、DBSCAN、归一化、标准化、F1、轮廓系数这些概念，用来提示「这只是一个把语义落到距离上的空间」，不要把它误会成地理坐标。

2.3 检索四步（06-P10）#

  1. 用户提问：「这篇综述对比了哪几种聚类算法？」
  2. 问题向量化：把问题也变成 768 个数字；
  3. 最近邻搜索：在向量空间里找离问题最近的片段；
  4. 召回 Top-K：取出最相关的 3–5 个片段。

课件给的示例相似度是 0.92 / 0.89 / 0.85（06-P10）。注意这三个数只是排序依据，不是可信度——相似度高只说明「语义接近」，不说明「这句话是对的」。这一条后面会反复用到。

2.4 一个完整的例子（06-P12）#

一篇 PDF 切成 500 tokens/段、共 50 个片段；提问后召回三段，每段都带来源页码：

K-Means 需要预先指定 K 值 ...        ← 来源：P.12
DBSCAN 基于密度，能发现任意形状 ...  ← 来源：P.15
层次聚类分为凝聚式和分裂式 ...        ← 来源：P.18

回答里用 [1] [2] [3] 标到具体片段，结论是「所有陈述均有文献出处，拒绝幻觉」（06-P12）。

这张图是整讲最该记住的一页。 它说明 RAG 的价值不止「答得准」，而是「每句话都可溯源、可审计」。科研场景里，后者比前者更硬。

2.5 30 分钟手搓一个 RAG（06-P15）#

课件给的最小闭环是零安装的三个组件：

组件 选择 理由
编排 LangChain Notebook / 命令行即可跑
嵌入 智谱 Embedding 公开接口 本地跑不动模型就直接用 API
向量库 FAISS LangChain 自动加载，免单独安装

五步：切分（PyPDFLoader，500 字/段）→ 嵌入（768 维）→ 入库 → 提问 → 召回（Top-K 拼上下文）。课件的话是「跑通一次，胜过听讲十遍」（06-P15）。

我的批注（不是课件原话）：手搓 RAG 的意义不是造工具，而是亲手撞一次「切分不当→召回失败」的墙。只有撞过，才会相信下一节「瓶颈不在检索」的结论。

3. 外循环 / 内循环：RAG 在智能体里的位置（06-P11）#

06-P11 把智能体内部拆成两个循环，这是理解「知识库怎么接进 Agent」的关键：

循环 干什么 组成
外循环（工具调用） 找资料 LLM 判断「需要查资料」→ 调工具箱（RAG 检索 / 记忆查询 / 联网搜索）→ 返回片段
内循环（上下文组装与生成） 拼上下文 系统指令 + 历史对话（前 5 轮）+ RAG 召回片段 + 记忆片段 + 当前问题

两个要点：

  1. 外循环检索到的一切，最终都要进内循环的上下文窗口。 所以「检索质量」和「上下文预算」是一对矛盾：召回越多越全，但挤掉的历史与指令也越多。
  2. 工具箱里 RAG 和记忆是并列的两个工具（06-P11 画的是 RAG 检索、记忆查询、联网搜索三格）。这解释了为什么 06 讲后半段要专门讲记忆——它不是 RAG 的子功能，而是另一个独立来源。

和 Task1 的接口在这里：外循环就是 Harness 的「调用工具」，内循环就是 Harness 的「整理上下文」。RAG 不是一个产品，而是 Harness 工具箱里的一个工具。

4. 从图书管理员到研究助手：传统 RAG vs Agentic RAG（06-P13、P14）#

传统 RAG Agentic RAG
隐喻 图书管理员 研究助手
流程 提问 → 向量检索 → 生成 → 答案 规划 / 决策 / 评估中心 → 多次检索 → 反思 → 报告
形态 线性、单向 循环、多步
会不会换关键词再搜 不会 会
适不适合复杂推理 不适合 适合

06-P14 给了一个调用时序，值得抄下来当模板：

用户："根据我昨天说的标准，评估这个新方案"
Agent → search_memory("评估标准")   → 返回："用户要求 ROI>30%"
Agent → search_rag("新方案 ROI 数据") → 返回："方案 B 首年 ROI 预计 35%"
Agent 综合记忆与文档 → "方案 B 满足您 ROI>30% 的标准 …"

这张时序图有两个信息量：

  • 记忆和 RAG 的调用是串行且互相依赖的：不先查记忆，就不知道「标准」是什么；
  • 答案的每个前提都能指认来源：30% 来自记忆，35% 来自文档。

我的批注：Agentic RAG 增加的不是模型能力，而是「检索策略」这一层。代价是循环成本与「检索表演」——反复换词查却始终不收敛。Task1 里 Harness 的次数/时间边界正是防这个的。

5. 效果上限在预处理（06-P17、P18、P20）#

课件列了三个现场高频现象（06-P17）：

现象 原因
化学式、公式类提问召回失败 公式被解析成乱码或图片，没有可检索文本
表格内容答非所问 表格被按阅读顺序拍平，行列关系丢失
扫描版 PDF 几乎搜不到 没有文本层，切分出来是空片段

归因一句话：效果上限由数据预处理决定，不在检索算法，也不在模型大小（06-P17）。课件配的工具是 MinerU：PDF → 结构化 Markdown，公式、表格识别准确，解析结果可直接入库。

预处理之后，成熟工具可以一键管理（06-P18，以 TiMEM Space 为例）：创建主题库 → 上传自动解析 → 问答带引用溯源 → 共享给团队；配套笔记功能（实验记录随手沉淀）、库管理（导入/导出/移动/重命名），以及用 MCP 连接器突破「知识只能在它内部问答」的边界。

再往上还有一张进阶清单（06-P20），课件明确说「今天不展开，遇到瓶颈时按这张图逐项排查」：

环节 要点
切分 Chunk overlap 重叠窗口，避免语义被切断
Embedding 选型与微调 单模态 vs 多模态；垂直领域可微调
Reranker 重排序 召回后再精排，显著降低噪音
向量库选型 Milvus / PGVector / ZVec，企业级部署
GraphRAG / LightRAG 图结构管理知识，面向多跳推理

我的批注：科研 PDF 还有两个课件没展开的坑——双栏排版会被读串行，参考文献列表会被当成正文召回。预处理阶段就应该把「页码 + 版面块类型（正文/图表/参考文献）」一起留下来，否则后面的引用只能落到「某篇 PDF」，落不到「哪一页哪一段」。

6. 记忆是什么：三种存储形态（06-P25~P28）#

06-P25 先把「记忆的存储形态」分成三类，并纠正一个常见误解：RAG 是统一的检索层，不是记忆本身的存储类型。

形态 隐喻 载体
知识库型 图书馆，静态只读 向量库 / 静态领域图谱 / PDF
文档型 笔记本，记录交互历史 Markdown / 文本 / JSON
图谱型 思维导图，随交互生长 记忆图谱：实体—关系—实体

6.1 本地 Markdown 目录（06-P26）#

memories/
  user_alice/
    profile.md          # 姓名、偏好、职业
    2026-08-28.md       # 当日记录
    project_timem.md    # 项目进展
优点 缺点
完全人类可读可编辑，VS Code 直接改 缺乏语义检索，只能关键词/正则
支持 Git 版本控制，排错一目了然 规模瓶颈，文件会臃肿到超 Token 上限
可整份塞进 System Prompt 作全局画像 需要人工维护结构

6.2 高维向量化存储（06-P27）#

优点 缺点
模糊与语义匹配强（「苹果」≈「Apple」） 人类不可读，纯数字数组难排错
无惧海量数据，ANN 毫秒级召回 修改成本高，改一句要重嵌入、更新库

6.3 怎么选：混合架构（06-P28）#

维度 本地 MD 目录 高维向量化
可读性 极高 极低
检索机制 精确匹配、路径路由 语义相似度、Top-K
维护成本 极低 较高（要维护 Embedding 模型）
最适用 核心 Prompt、全局画像、系统规则 单次历史对话、海量历史轨迹

课件的结论是：现代 Agent 往往采用混合架构——MD 存核心且需人工维护的规则与画像，向量库存海量对话轨迹与执行日志（06-P28）。

我的批注：这个选择的本质不是技术偏好，而是「谁维护、怎么排错」。MD 能被 git diff 看见，向量库不能；反过来，向量库能扛住十万条轨迹，MD 不能。我的做法会是：画像与规则用 MD（可 review），轨迹用向量库（可增长），两者用一个 id 关联。

7. 轨迹、记忆、技能：三层颗粒度（06-P29~P32）#

06-P29 给了一条从细到粗、从短到长的轴：

层级 内容 时间跨度 产物
L1 任务轨迹 一次对话 / 一次实验 短 运行记录、日志
L2 跨会话记忆 习惯、偏好、长期认知 中 画像、周报
L3 技能 可复用的能力模块与 SOP 长 Skill

课件的原话是：轨迹会封存，记忆会跨会话累积；技能 = 从多次成功决策中提炼的标准化流程（SOP），是记忆的产物，会被不断复用（06-P29）。

这就把 Task1 的 Skill 和 Task2 的记忆接上了：Skill 是记忆的最高抽象层。 一次成功的轨迹，先变成记忆，再从多次记忆里提炼成 Skill。

7.1 人脑类比（06-P30、P31）#

人脑 AI 容量/生命周期
感觉记忆 上下文窗口 当前输入，4K–128K tokens
工作记忆 会话缓存 本次会话历史，会话结束清空
长时记忆 时序记忆树 跨会话持久化：主题摘要 → 趋势 → 画像

长期记忆内部再分三类（06-P30）：语义记忆（事实，「研究方向是机器学习」）、情景记忆（经历，「上周二 K=5 表现最好」）、程序记忆（技能，「基线→标准化→调参」的 SOP），物理载体是向量库/数据库/文件系统。

课件那句「不是在造数据库，是在给数字生命体造海马体」（06-P31），点明了记忆系统的目标不是存储，而是「形成可用的经验」。

7.2 知识记忆 vs 规则与技能（06-P32）#

知识记忆 规则与技能
本质 世界是什么样的 遇到事情该怎么做
隐喻 海马体 / 档案馆 基底核 / 工具箱
形态 事实·偏好·经历·文档 SOP·脚本·函数调用
作用 提供决策素材 约束并驱动行为

两者是互生关系：知识为技能提供决策素材，技能基于知识执行落地动作。只记不做，等于一堆笔记；只做不记，等于每次从零开始。

8. 时序分层与读写代谢（06-P33~P35）#

8.1 L0–L3 金字塔（06-P33）#

层级 颗粒度 更新节奏
L0 原始碎片 对话原文与时间戳 实时
L1 主题摘要 主题级 每日归档
L2 周报 / 周期总结 趋势级 每周更新
L3 动态画像 人格级 持续演化

左边是「聚合方向」（自下而上层层提炼），右边是「查询展开」（按需自上而下展开）。参考工作是 TiMem（ACL 2026，arXiv:2601.02845）。

8.2 写入与读取的完整代谢（06-P34）#

写入路径是一条层层提纯的流水线：

原始交互 100% 信息量（高噪声）
  → 主题摘要 30%（去噪留干）
  → 每日归档（时间线整理，形成脉络）
  → 趋势总结（周期性回顾，发现演化）
  → 人格画像 5%（核心认知，高精度）

信息密度递减，抽象层级递增。存的介质也分开：原始对话 → 向量库；摘要 → 结构化 JSON；画像 → Markdown。

读取路径则相反：用户提问 → 触发检索 → 记忆重塑（按当前需求展开、拼接片段）→ 上下文组装（注入 System Prompt）→ 喂给模型。

8.3 记忆重塑：召回只是第一步（06-P35）#

课件举的例子很具体：召回 10 条相关或无关的记忆，其中混着「周三：吃火锅」这种噪音；然后

  1. 过滤相关性（扔掉吃火锅）；
  2. 融合去重（合并重复记录）；
  3. 时间排序（理清先后）；

最终留下 5 条高质量记忆喂给 LLM。课件的话是：搜出来还不够，要筛选才有效——召回只是第一步，过滤整理才决定上下文质量（06-P35）。

我的批注：压缩是有损的。L0 原始记录必须保留「永删」的指针，否则画像一旦出错就无法复核。这和 Task1 的「不要相信 Agent 的自我总结，要相信它留下的原始记录」是同一条工程约束。

9. 冲突：记忆里最像科研的部分（06-P36）#

课件给的例子几乎就是科研日常：

  • 上周的记忆：在调 KNN，K=5 效果最好，先沿这条路线做；
  • 今天的记忆：KNN 对异常值太敏感，改用密度聚类 DBSCAN 试试。

系统怎么发现矛盾？新记忆与历史画像做语义比对，若语义冲突且时间跨度大，就触发冲突检测（06-P36）。处理有三种策略：

策略 做法 代价
① 打时间戳，新覆盖旧 默认策略，以最新决定为准 丢掉「为什么改」
② 保留两者，标注「观点变化」 把矛盾本身记成一条记忆 需要额外存储与阅读成本
③ 让大模型裁决 结合上下文判断是「一次实验受挫」还是「路线真实切换」 裁决可能错，且要留依据

课件的落点是：实验会失败，路线也会调整；记忆系统的价值在于能发现「方向变了」，并跟着课题一起更新（06-P36）。

我的批注：科研里「路线变更」本身往往就是结论的一部分。默认的「新覆盖旧」最省事，但会把「为什么放弃 KNN」这个最有价值的信息删掉。我倾向于默认用②，至少对「方法/参数/结论」三类记忆不覆盖。

10. 选型与共享（06-P38~P42）#

10.1 市面方案横评（06-P38）#

方案 时序分层 自动摘要 中文支持 MCP 一句话定位
Mem0 版本时间戳 需自定义 英文为主 ✅ API 简洁，适合动手环节
Zep 时间图谱 原生支持 英文为主 ✅ 企业级会话上下文记忆
Letta 核心/归档 需自定义 英文为主 ✅ 原 MemGPT，虚拟内存类比
TiMEM 原生支持 原生支持 中文优先 ✅ 时序分层记忆引擎，支持私有化部署

选型口诀（06-P38）：快速体验/英文为主选 Mem0，复杂关系推理看 Zep，企业级要自动总结看 Zep/Letta，中文+时序分层+私有化+长周期看 TiMEM。

10.2 有记忆 vs 无记忆（06-P39）#

无记忆 有记忆
首轮 分析 KNN 在 Iris 上 K=3、82% 的原因 同左，但记住 Iris / K=3 / 82%
重开窗口后问「先标准化会不会好点」 「标准化通常有帮助，请问你具体在用哪个数据集？」 「针对你 Iris 上 82% 的问题，KNN 对距离敏感，标准化后权重一致，很可能有效。」
差别 完全断片，反复询问 指代消解成功、上下文继承

课件总结：接入记忆引擎后，回答从「通用模板」变成懂上下文的「专属建议」（06-P39）。

10.3 MCP：跨智能体的「神经系统」（06-P40~P42）#

06-P40 的图景：代码助手、编程智能体、文献助手、实验记录助手、日程/周报助手，各自通过 MCP 连到同一个记忆引擎，背后是统一记忆库（时序分层）+ 统一知识库（RAG）+ 统一工具库（Skills）。没有 MCP 就各记各的、换个助手就失忆；有了 MCP，接入只需要「服务地址 + 访问密钥」。

06-P42 补了一句关键区分：Skill = 使用规则，定义何时读记忆、何时写记忆。 也就是说，MCP 解决「接得上」，Skill 解决「什么时候读写」——这和 Task1 里 MCP 与 Skill 的分工完全一致。

我的批注：跨智能体共享把「记忆污染」的面放大了：一个助手写错，所有助手都记错。所以共享记忆必须配写入审计（谁写、依据什么、可否回滚），这比接入本身更重要。

10.4 科研流程各环节，用知识库还是记忆（06-P45）#

环节 用什么 理由
文献调研 知识库 查得到、有引用
实验过程 记忆 记得你、跨天连续
数据分析 知识库 + 记忆 代码入库、过程入记忆
论文写作 两者协同 引用靠库、风格靠记忆

课件的小结是：静态资料用知识库，动态过程靠记忆，底层是同一个统一记忆引擎（06-P45）。这张表正好对应 Task2 的任务描述——「搭建文献知识库」对应第一行，「整理和使用实验记录」对应第二行。

最后，06-P51 给了记忆的三步演进：外挂记忆（工具化）→ 内化记忆（模型层记录）→ 记忆长在参数里（持续学习）；同时点出三个挑战：隐私边界、遗忘机制、冲突消解。课件的判断是短期内外挂更灵活可控，长远趋势是记忆伴随协作「长」进参数（06-P51）。

11. 07 讲：为什么要自建领域数据集（07-P02）#

07 讲从一个真实困境开始：想快速全面了解一个新领域、或者写综述，需要有「全面、及时、维护良好」的数据集（07-P02）。案例是 Open Astronomy Catalogs——设想每个子领域由社区自发维护数据库、通过 GitHub 协作提交，现实却是：

  • 数据提交与整理入库依赖专家大量重复劳动，运维难以为继；
  • 核心发起者离开后项目停止维护；
  • 只有 TNS、开放系外行星数据库等热门领域靠成熟组织与资金存活，冷门子领域始终缺口。

课件的判断很硬：本质上是经济问题而非技术问题；AI 的作用是把「专家重复枯燥的智力劳动」压到「API 账单的价格」（07-P02）。

这句话解释了 Task2 为什么要同时讲知识库和数据集：

  • 知识库是「对内」的：让自己的智能体查得到、答得出；
  • 数据集是「对外」的：让整个领域（以及其他人的 Agent）能直接使用、不必重建。

12. 四代方法：控制权在谁手里（07-P03~P06）#

07 讲用同一个任务（从高速星论文里提取候选）比较了四种做法：

方法 做法 优势 缺陷 控制权
一、单轮聊天机器人 上传 PDF，一句话说需求，单轮得答案 简单、直接、零门槛 手动提供资料、手动整理结果，自动化最低 人
二、AI 产品深度研究 云电脑里的 Agent 自动搜集、分析、出报告 一句话启动完整调研 过程不透明、资源受商业限制 平台
三、通用 Agent 本地运行，任务拆成 ToDo，并行子代理逐篇提取 流程透明灵活、资源不受限；上下文隔离提升质量 对单一数据集过重、结果难审计；问题定义不严，执行必然漂移 模型
四、自建科研数据 Harness 自己定义问题，搭「文献 → 数据产物」工作流，程序化验证 清晰透明、掌控力最强 搭建耗时（作者项目连续 4 个月以上） 自己

几个值得记的细节：

  • 方法二的数量级问题：要求调研 2018 年至今发现的高速星，报告只收录 21 条，而实际应有上百颗（07-P04）。过程不透明，所以「少了」也无法归因。
  • 方法三的漂移：并行子代理提取后，结果里混入了 bound（束缚）条目——红色 = unbound，绿色 = bound，说明 Agent 偏离了最初的约定（07-P05）。课件归因：问题定义不严，执行必然漂移。
  • 方法四的定义：Agent = LLM + Harness；Harness 本义是马具，大模型是力大却难控的烈马，需要一套工程组件约束它按你的需求完成任务（07-P06）。方法要点是「自己定义问题 + 程序化验证（每条结果可追溯到原文具体位置）」。
  • 成本是明示的：作者的项目连续工作 4 个月以上，并把项目蒸馏成可复用的搭建指南 Stella-meta 开源（07-P06）。

我的批注：四代不是替代关系，而是按任务规模选。单篇临时提取用方法一就够；只有「领域级、要复用、要发表」的数据集才值得方法四。看到「4 个月」这个数字，就该明白方法四的代价不是技术门槛，而是持续投入。

13. 质量：自建 Benchmark 三层（07-P07）#

为什么需要 Benchmark（07-P07）：

  • 用分数直观量化新系统与旧版本、同类竞品的能力差距；
  • 知道如何评价一个工作，就知道这个工作该怎么做；
  • 重要 Benchmark 奠定领域基础——ImageNet → AlexNet、CASP → AlphaFold。

文献数据提取的三层评价模板：

层级 检查什么 典型错误
L0 格式层 每篇文章的提取结果是否符合输出格式要求 字段缺失、类型错、JSON 不合法
L1 实体层 提取的科学实体条目与专家结果是否一致 漏抽、多抽、别名未归一
L2 数值层 每个科学实体对应的数值是否准确 单位换算错、有效数字错、看错列

课件提到作者与合作者花一个多月（人机结合）提取 50 篇文献，构建了高速星提取的 Benchmark，据此量化准确率、召回率等指标（07-P07）。核心原则是一句话：有效衡量你真正关心的东西。

我的批注：三层其实对应三类误差，修法不同——L0 可以完全程序化（schema 校验），L1 需要实体对齐规则（别名表、同义词），L2 需要数值容差（单位、精度）。Benchmark 没建好时，报「准确率 90%」没有意义，因为不知道 90% 是在哪一层算的。

14. 发布：从 FAIR 到 AI-Ready（07-P08）#

为什么要发布（07-P08）：

  • 同一领域重复构建同一数据库，是对资源的浪费；
  • 识别领域最重要的问题，构建好并开放给其他研究者；
  • 他人免重建即可开展研究，你也能收获领域影响力。

数据集构建原则分两层：

层次 原则 落地
FAIR（经典数据科学） 可查找 Findable、可获取 Accessible、可互操作 Interoperable、可复用 Reusable 元数据、开放许可、标准格式、版本
AI-Ready（面向 Agent 使用者） ① 结构化：便于被其他 Agent 用程序调用；② 可追溯：每条数据可回溯原始出处，便于核验；③ 有治理：明确说明局限，让 Agent 知道何时、如何使用 Schema、证据列、适用边界文档

FAIR 出处是 Wilkinson et al., 2016, Scientific Data；案例是作者的 STELLA HVS Catalog 网站（07-P08）。07 讲最后的总结把它压成四句：数据缺口、方法进阶、动手实操、评估与共享（07-P9）。

我的批注：三条 AI-Ready 原则里，「有治理」最容易被忽略，却最影响可用性。没有「适用物种/平台/参考版本/已知偏差」的说明，下游 Agent 会把它当成普适真理来用——这比数据少几条更危险。

15. 把两讲拼成一条流水线（我的整合）#

三条流水线，对应三类资产：

论文 PDF ──解析(MinerU)──→ 结构化 Markdown ──切分/嵌入──→ 知识库 ──检索──→ 带引用的回答
实验记录 ──写入(时间戳)──→ L0 碎片 ──聚合──→ L1 摘要 / L2 周报 / L3 画像 ──召回──→ 上下文里的「记得你」
论文表格 ──抽取(模板)──→ 候选记录 ──程序化验证──→ Benchmark(L0/L1/L2) ──发布──→ 数据集(FAIR + AI-Ready)

三类资产的分工：

维度 知识库（RAG） 记忆 数据集
管理对象 公共静态知识 个人动态经历 结构化的领域事实
更新方式 主动上传新 PDF 每次交互自动写入 按版本重新抽取
证据单位 页码 / 段落 时间戳 / 会话 原文位置 + 字段
主要失败 解析差、切分差、召回偏 污染、冲突、过时 格式错、实体错、数值错
评价指标 召回率、引用准确率 指代消解、冲突发现 L0/L1/L2 准确率、召回率
一句话 查得到 接着做 别人能接着做

共同底线只有一条：每条结论都能回到原文或原始记录的具体位置。 06 讲的引用页码、记忆的时间戳与冲突标注、07 讲的「每条结果可追溯到原文具体位置」，说的是同一件事。

16. 迁移到自己的课题（以组学为例）#

这一节是我的迁移练习，不是课件内容；目的是把两讲的方法落到自己的数据上。

资产 在本领域的落地 关键字段/动作
文献知识库 按「数据 / 方法 / 结论」切分文献，而不是按章节 物种、平台、样本量、基因/变异、图号表号；引用落到 figure/table
实验记录（记忆） 每次分析写一条带时间戳的记录 数据版本、参考基因组版本、命令与参数、指标、判断；方案变更单独记一条
数据集 变异/表达/影像表 → Schema chrom/pos/ref/alt/rsid、AF/OR、证据行号；L0 schema 校验、L1 实体对齐、L2 数值容差
治理 每份数据集配一页 README 适用物种/人群、平台、参考版本、已知偏差、不可用于什么

三条最小动作（按投入从低到高）：

  1. 先把 L0 做好：解析（保页码）、切分（保图号表号）、引用可跳转。不要一上来就 GraphRAG。
  2. 给实验记录定一个最小模板（日期 / 数据版本 / 命令 / 指标 / 判断 / 下一步），坚持写两周，再看哪一列真正被用到。
  3. 给已有的一张表建一个 10 篇文献的微 Benchmark：L1 抽实体、L2 核数值，先量出基线，再谈优化。

18. 我提炼的九条（用自己的话）#

  1. RAG 的价值是「可审计」，不只是「答得准」。 每句话带页码，才有资格进科研流程。
  2. 相似度不是可信度。 0.92 只说明语义近，不说明结论对；核对要另做。
  3. 瓶颈通常在入库前。 公式、表格、扫描件解析不好，换多大的模型都救不回来。
  4. 知识库与记忆的分工是「公共静态 vs 个人动态」。 文献找 RAG，实验找记忆，两者拼出「下一步试什么」。
  5. 记忆是代谢，不是仓库。 写入层层提纯（100%→5%），读取按需展开；只存不炼，等于没记。
  6. 召回只是第一步，重塑才决定上下文质量。 相关性过滤、去重、时间排序，三步缺一不可。
  7. 冲突处理是记忆系统最像科研的部分。 默认「新覆盖旧」会丢掉「为什么改」，那往往是最有价值的信息。
  8. 方法论上的进阶 = 控制权的回收。 Chatbot → 深度研究 → 通用 Agent → 自建 Harness，可控性与成本同向上升；按任务规模选，不要一律上最重的。
  9. 数据集的门槛是「评价」，不是「抽取」。 没有 L0/L1/L2 的 Benchmark，「准确率」无从谈起；没有「治理」说明，数据集会被误用。

19. 自测（先答，再对要点）#

# 问题 要点
1 模型的三个知识缺口是什么？ 知识过时、私有盲区、幻觉（06-P7）
2 嵌入、召回、重排、检索四个词的关系？ 检索是总称，包含召回与重排；嵌入是把文本变向量（06-P8）
3 建库三步与课件参数？ 切分（500 字/段）→ 嵌入（768 维）→ 向量库（06-P9）
4 RAG 答案为什么要带 [1] 与页码？ 可溯源、可审计，拒绝幻觉（06-P12）
5 外循环与内循环分别是什么？ 外循环找资料（工具调用），内循环拼上下文（06-P11）
6 传统 RAG 与 Agentic RAG 的差别？ 线性单向 vs 循环多步、会规划与反思（06-P13）
7 为什么说瓶颈在数据而不是检索？ 公式/表格/扫描件解析差，召回必然失败（06-P17）
8 MD 目录与向量库各自的缺点？ 无语义检索/规模瓶颈 vs 不可读/修改成本高（06-P26、P27）
9 L1/L2/L3 分别指什么？ 任务轨迹 / 跨会话记忆 / 技能 SOP（06-P29）
10 时序分层 L0–L3 与更新节奏？ 原始碎片（实时）→ 主题摘要（每日）→ 周报（每周）→ 画像（持续）（06-P33）
11 记忆重塑的三步过滤？ 相关性 → 融合去重 → 时间排序（06-P35）
12 冲突处理的三种策略？ 时间戳覆盖 / 保留标注观点变化 / 大模型裁决（06-P36）
13 07 讲四种方法的递进逻辑？ 自动化与可控性递增，成本递增（07-P03~P06）
14 通用 Agent 为什么会漂移？ 问题定义不严；执行偏移约定（07-P05）
15 Benchmark 三层各查什么？ 格式 / 实体 / 数值（07-P07）
16 FAIR 与 AI-Ready 的区别？ 经典数据原则 vs 面向 Agent 的结构化/可追溯/有治理（07-P08）
